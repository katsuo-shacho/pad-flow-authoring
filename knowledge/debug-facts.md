# デバッグに使える製品の挙動（公式要約＋観察）

出典: Microsoft Power Automate documentation（desktop-flows/debugging-flow, errors, monitor-run-details, troubleshoot, configure-desktop-flow-logs。CC BY 4.0、本プロジェクトによる要約）。
「観察」と書いた項目は公開情報での一般的な観察で、版・環境により異なる。自分の PC で確認してから頼る。

## デザイナーのデバッグ機能（公式）
- **実行／一時停止**: F5 で実行、実行中は Ctrl+Pause で一時停止して変数を点検できる。
- **ブレークポイント**: 行番号の左をクリック（赤い点）。そこで止まる。
- **次のアクションを実行**: 1アクションずつ進め、止まるたびに変数ペインで値を見る。
- **ステッピング モード**（Debug メニューで ON）: ステップ オーバー F11、ステップ アウト Shift+F11。サブフローに入る／抜ける制御。
- **ここから実行**: アクションを右クリック → Run from here。前のアクションを飛ばして途中から走らせる（前段の変数が未定義になることに注意）。
- **実行遅延（Run delay）**: ステータス バーの値。デザイナー実行では各アクション後にこのミリ秒だけ待つ。デザイナーとコンソールで速度が違う理由の一つ。

## エラーの種類と見方（公式）
- **設計時エラー**: 必須引数が空、未定義変数など。実行前に止まる。エラー ペインの Type / Description / Subflow / Line で場所が分かる。
- **実行時エラー（例外）**: 無効なパス、要素が見つからない等。ダブルクリックで、メッセージ・場所（サブフロー・行・アクション）・修復案（Excel 系のみ）・エラー詳細（相関 ID と技術的説明）。
- **警告**: 止まらないが、無限ループ等の疑いを示す。

## エラー処理の選択肢（公式）
- アクション単位「エラー発生時」: 再試行（回数・秒）、続行（次のアクションへ／同じアクションを繰り返す／ラベルへ移動）、追加ルール（変数を設定／サブフローを実行）、Advanced で例外名ごとに分ける。
- ブロック単位「ブロック エラー発生時」: 同じ選択肢に加え、範囲外アクセスのような論理エラーも捕まえる。再試行は**ブロックの先頭から**やり直す。アクション単位の設定がブロック設定より優先。
- **直前のエラーを取得（Get last error）**: 名前・場所・アクションのインデックス・サブフロー・詳細・メッセージの6プロパティ。「エラーをクリア」で二重取得を防ぐ。
- Robin 上の書き方と制約（ハンドラー内は SET/CALL/GOTO/THROW のみ、ON ERROR は可のアクションだけ）は robin-rules.md T20/T21。

## 実行ログ（公式＋観察）
- **ポータル（Premium）**: 実行の詳細ページに、アクションごとの開始時刻・サブフロー・アクション インデックス（＝行番号）・所要時間・状態。ログ V2 かつ v2.52 以降なら実行中にほぼリアルタイムで流れる（progressive logging）。
- **ローカル（観察）**: コンソールから実行したフローは、ユーザー プロファイル下の Power Automate Desktop のデータ フォルダー（`Console\Scripts\<フローID>\Runs\<実行ID>`）に実行ごとのフォルダーができ、アクション履歴（時刻・結果）の JSON、実行結果の JSON、エラー時のスクリーンショットが残る。フォルダー名は GUID なので更新日時で探す。自動削除されないので溜まる。
  → 時間解析はこのアクション履歴を `scripts/analyze_timing.py` に食わせるのが早い（時刻＋アクション名の行にして渡す）。
- **デザイナー実行はコンソール実行より遅い**（Run delay と監視のため）。性能計測はコンソールから。
- **機械ログ**: Troubleshoot ツールの「ログのエクスポート」でデスクトップに zip。接続・サービス側の問題はこれ。

## 止め方（公式）
- 通常停止と**安全停止**がある。安全停止は終了処理を走らせてから止める（safe-stop）。自走検証で「止まったら自分で止める」はこちらを使う。
