# 定石（旧方式）: ダウンロード型処理の「受付」と「完了確認」を分離する

**旧方式。** `<a download>`＋Downloads 監視を前提にした整理で、現行は patterns-browser-fetch.md（ページ内 fetch → base64 → PowerShell 保存）。受付／完了監視／最終照合を分ける考え方と、ログ・該当なしの分類は今も有効。

出典: 本プロジェクトの自前検証（ダミー環境での PAD フロー改修）から整理した設計知見。確認版は未記載（追記時に PAD の版を書く）。製品の一般保証や速度の実測結果ではない。既存の一括処理原則は workflow/02-design.md を参照。

## 処理の単位
- 実行単位：ユーザー情報・実行開始日時・設定を一度取得し共有する。ファイルの取得日時は別の意味なので、実行開始日時で代用しない。
- ID単位：対象ページの識別と一覧の安定を確認し、全検索語をまとめて照合する。ID・検索語・リンク・一意な予定キーを持つ一覧を確定し、ブラウザー外にも保持してから取得を開始する。
- 取得受付：JSの戻り値は保存完了とは限らない。予定・受付・完了・失敗を分け、受付後は次IDの検索と受信を重ねる。ページ遷移で非同期処理が失われない実行場所を選び、並列数・受付間隔・タイムアウトを設ける。具体値は環境ごとに検証する。
- 全IDの後：予定一覧に対する完了監視と最終照合をまとめる。既存ファイルとの誤一致、一時ファイル、サイズ・受信情報、PDF内容の確認は省かない。移動・改名は検証済みファイルを最後に一括処理し、個別失敗を記録する。

一覧の安定は「以後追加されない」保証ではない。確定時点の範囲を対象にし、完全件数を保証できない場合はその制約を明示する。同じリンクが複数検索語に一致するときは、取得の重複と検索結果への所属を別管理する。

## PADとの往復を減らす
- ソースの行数ではなく、実行されるアクション数とスクリプト呼出回数を見る。深いループ内の初期化・文字結合・型変換を優先して見直す。
- 前後のスクリプトへ整形・集計を寄せ、PADへは必要な結果をまとめて返す。短いスクリプトを増やすだけでは往復削減にならない。
- 同じ安全確認の重複は統合する。ただし次の操作を安全に行うための確認と、最後にまとめられる完了照合を混同しない。

## ログと準備案内
- バックチェック用ログは、実行者・日時・対象・結果を中心にする。件数の総括は先頭に一度だけ。ID、検索語でまとめ、成功はファイル名の1行、失敗だけ短い理由を添える。共通パスやIDの繰返しを減らす。
- 振り分けログは、総括・移動条件・各ファイルの結果に絞る。移動前後のパスは正確に区別し、同一場所への移動なしを実移動と混同しない。ログも振り分けるかは利用者設定にする。
- 準備中の案内は、状態＋補足1行、条件確定後の件数・内容の表程度にする。既存の処理境界で更新し、取得開始後は更新しない。案内だけのブラウザー再起動・再遷移・監視ループを増やさない。
- 入力値はHTML文字列として挿入せず、テキストとして描画する。セッション確認は見た目の表示とは分離し、ダミー環境の認証方式を実サイトへそのまま移植しない。

## 最小限の確認
変更した整形・集計・状態遷移はまずコード側で確認し、画面確認は取り込み・保存・表示固有の箇所に絞る。必要な操作前後の確認は残すが、同じ画面の画像取得や無関係な全件ダウンロードを繰り返さない。速度比較ではページ待ち・受信待ち・処理時間を分け、重なる待ち時間を二重に差し引かない。

公開するのは設計知見とダミー例だけにし、実ログ・実ユーザー名・端末名・個人パス・認証情報を含めない。

## 追記（自前検証からの一般則。PAD 2.73 / Classic、模擬サイト）
- **取得方式は2つを用意し、JS 側で切り替える**: (a) ページ内 `fetch` → base64 → PowerShell で `%PDF-` 署名・サイズ・保存後サイズを検証して保存（ブラウザーのダウンロード設定・`(1).pdf`・保存先ズレに依存しない）。(b) `<a download>` クリック → 一意名 `PAD_CLICK_<UUID>.pdf` だけを対象に Downloads を監視。別オリジン（CDN）配信で fetch が拒否されるサイトは (b)。切替は JS と PowerShell の中に閉じ、PAD の深いループに方式別 IF を足さない。
- **数 MB の base64 を `ExecuteJavascript` の戻り値に載せる上限は未確認**。バッファ上限（MB）を設定に持ち、超えたら次の受信を待たせる。
- **ログイン判定は「検索欄が見えるか」**。見えなければダイアログで人がログイン → OK で続行（回数上限つき）。サイト固有のログイン URL をコードに書かない。
- **サイト適合は `data-*` 属性に頼らない**。リンクの href か文字が `.pdf` に一致するものを対象にし、「一覧が n 秒変わらない かつ 検索前と違う」で確定。結果が出た印・失敗の印（REGION 02）は空でも動く設計にする。
- **VBScript を配布物の土台にしない**（Windows 11 24H2 以降オンデマンド機能化）。ファイル操作は PowerShell、ページ操作は JavaScript。
- **構成は Main 1本・サブフロー無し**が配布しやすい（貼付1回）。900 行を超えるなら 2 本に分け、連携は「結果画面のボタン → フローの実行」。フロー ID は PC ごとに違うので REGION 00 に持つ（空ならボタンを出さない）。
- **振り分け（ファイル移動）側**: リンク判定は `fsutil` を 1 件ごとに起動せず PowerShell でフォルダーごと 1 回（キャッシュ）。大文字小文字の厳密一致は Windows では無意味。処理中ログ→確定ログの読み戻し照合は過剰、確定ログを書いて処理中ログを消す。
- **「該当なし」は3種類に分けて文言と集計単位を決める**: 一覧は取れたがワードに合う PDF が無い（ワード単位）／一覧は取れたが PDF 0 件（ワード数ぶん）／一覧が取れない（ID 単位、ページ読取失敗）。
- **ID 一覧の出力**は HTML（Edge で見る・パスをコピー）と HTA（Explorer で開く。`mshta` が止められた PC では HTML）。ブラウザーのページから Explorer は起動できない。
- **貼付で実際に起きた失敗**: ON ERROR 内に EXIT/SET（→ GOTO のみ）、変数名 `Wait`（予約語で無言却下 → `WaitResult`）、`Text.Replace`（正しくは `Text.Replace.ReplaceText`、`ComparisonType` 必須）、`@@statistics_` ヘッダーを貼った。
- **性能比較はサイトの遅延設定を揃えてから**。並列数 1 と 5 の差、1 ID の検索〜一覧確定、PDF 1 件の受信〜保存、を分けて測る。
