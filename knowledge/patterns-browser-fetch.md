# 定石: 認証付きサイトからの取得はブラウザーの中で（fetch → base64 → PowerShell 保存）

出典: 本プロジェクトの自前検証（PDF 取得・振り分けフローを模擬サイトと実サイトで動かした2日間、PAD 2.73 / Classic）。製品の一般保証ではない。
旧方式（`<a download>`＋Downloads 監視）は patterns-download-pipeline.md。本定石が現行。

## 1. ブラウザーの中でやれることはブラウザーの中でやる
- 「JavaScript の実行」はページの中でコードを動かす。ログイン状態・Cookie・同一オリジンの特権はページ内の JS だけが持つ。PAD の「Web からダウンロード」や外部ツールは持たない。
- 認証付きサイトからの取得: **JS で `fetch(url, {credentials:"include"})` → `arrayBuffer` → base64 文字列で PAD に返す → PowerShell でファイルに書く**。
- ブラウザーのダウンロード機能（`<a download>`・Downloads 監視）は使わない: 保存先設定・「保存場所を確認」・複数ダウンロード許可・`(1).pdf` に振り回される。
- 制約: 同一オリジンの URL のみ（CDN など別ドメインは CORS で不可）。1件のサイズは base64 で 1.33 倍になり PAD 変数を通る（30MB 程度まで実績あり、上限は未検証）。HTTP サイトでは secure-context 限定 API（`crypto.randomUUID`、`navigator.clipboard` など）を使わない。

## 2. 状態は1か所に置く
- 複数タブ・複数回の JS 呼び出しにまたがる処理は、**最初に開いたタブの `window` オブジェクト**を台帳にする（`window.__padQ` など）。PAD 変数に状態を散らさない。
- 作業用タブは使い捨て（一覧を読んだら閉じてよい。閉じない設定も用意）。
- 受信は台帳側のキューで走らせ、PAD は「予約 → 後で回収」の2周にする。同時受信数・開始間隔・未保存バッファ上限は台帳側で制御。

## 3. 値は JSON で渡す。文字列に直書きしない
- `%変数%` を JS や PowerShell の引用符の中に展開すると `\` `"` `$` で壊れる（実例: `DOMAIN\user` を JS 文字列に入れて `\` がエスケープ扱い）。
- PAD で CustomObject を組み → `ConvertCustomObjectToJson` → JS 側で `const p = %Json%;` と受ける。
- PowerShell へは一時ファイル経由（`File.GetTempPath` → `WriteText` → PS が読む → 同じファイルに結果 JSON を書き戻す → `ReadText`）。大きいデータ（base64）は「1行目＝名前、2行目以降＝本体」。

## 4. 待ちは実時間で、判定はブラウザー側で
- PAD のアクション1回は 0.3〜1 秒かかる。「0.5 秒 × 120 回」は実時間が読めない。
- JS で `Date.now()` を使い経過秒で打ち切る。PAD のループ回数は保険（大きめ）。
- 目安: 結果待ち 30 秒、1件の受信 60 秒、ID 単位の回収待ち 180 秒（予約時刻から）。

## 5. ページの状態判定
- **新しい文書か**: 検索前に `performance.timeOrigin` を控え、変わったら遷移済み。
- **目的の表示が出たか**: `document.body.textContent` の空白・改行を潰して部分一致。`{ID}` のような穴を設定に用意。`<input>` の value は textContent に含まれないので、自分が打った ID を誤検出しない。
- **一覧が落ち着いたか**: リンクの (文字, href) の署名が N 秒変わらない。
- **失敗の印**: あれば CSS セレクターで即失敗（待たない）。
- サイト固有の `data-*` 属性に頼らない。セレクターは id が無ければ `input[name="…"]`。
- 対象リンクは「`.pdf` で終わる」ではなく「リンクに必ず含まれる短い固定部分」の正規表現で。

## 6. 設定は3段に分ける（patterns-config-object.md）
- REGION 00 サイト固有（URL・検索欄・ボタンの3つ程度）。
- REGION 01 文章とフォーム初期値（画面の文言・ログの行の形・初期値。`{ID}` `{名前}` などの穴を持つテンプレート）。
- REGION 02 固定の数値（秒数・同時数）。
- 文言とログの形はコードを触らず直せる。サイト設定は自由入力の画面に出さない（取り違えの元）。確認画面には接続先とセレクターを編集不可で小さく表示。

## 7. 画面と終わり方
- 確認（チェック必須）と入力を1画面で、枠と区切り線で分ける。
- 結果画面の「開く」系ボタンは開くだけで画面が残る。終わるのは「閉じる」だけ。
- ログは頭を短く（件数・実行・保存先・照合）、本文は固定形式、末尾は空行＋`[終了]`。

## 8. 最終照合
- 件数一致は照合ではない。成功全件について「同名が存在」「サイズが受信バイト数と一致」「予定外のファイルが無い」の3点。
- 照合は PowerShell で。名前は前後の空白・改行を落としてから比較。
