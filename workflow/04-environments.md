# 環境別の進め方: AI 内で完結する層と、エージェントが要る層

目標は「貼る前にほぼ100点」。そのために AI 内でできることを全部やり、実機は最後の確認に使う。

## 共通（どの環境でも AI 内で完結する）
1. **設計**: 02-design.md。一括化・ループ削減・ループ内ブロック削減の提案はここで出す（実機は不要）。
2. **組立**: knowledge/robin/<module>.md の検証済み例をコピーして値を差し替える（二表方式）。推測で書かない。
3. **模擬貼付テスト（セルフチェック）**: 実機が無くても、以下を robin-rules.md に照らして1行ずつ確認し、結果を表で出す。
   - V3: `%` が文字列の外に無い
   - S6/S7/S9: 文字列内の `'`、変数直前・末尾の `\`、対になっていない `%`
   - N11/N13: 予約語の変数名・プロパティ名、未定義変数（SET／出力／ループ変数のどれかで定義済みか）
   - T16: IF/LOOP/SWITCH/BLOCK と END の対応、1行1文
   - T19/T20/T21: ELSE IF (アクション) 禁止、ハンドラー内は SET/CALL/GOTO/THROW のみ、ON ERROR は on_error:true のアクションにだけ、例外名は宣言済みのもの
   - K1/K2/V4: ID が KB にある、引数名が KB と一致、enum が完全修飾で許可値
   - T23: ヘッダー・FUNCTION を貼らない。サブフローは Designer で作って本体だけ貼る
   出力例: `行 | 内容 | 判定 | 根拠（規則番号 / KB の ID）`。全行「OK」になるまで直す。
4. **静的レビュー**: 03-principles.md の観点で、まとめられる処理・減らせるループ・ループ内の余計な SET/WAIT を**優先度付き**で提案する（高: 実行時間や失敗率に直結 / 中: 保守性 / 低: 体裁）。

## A. Copilot だけの環境（ツールなし・ファイル実行なし・画面操作なし）
- スキルを読み込めないので、必要なファイルだけを会話に貼る。`scripts/make_prompt_pack.py --modules excel,file,folder` で
  「robin-rules.md ＋ 指定モジュールの robin/*.md ＋ 03-principles.md 要約」を1本のテキストにまとめ、それを先頭に貼ってから依頼する。
- 模擬貼付テストは上記3を Copilot にやらせる（「規則番号を付けて1行ずつ判定して」と頼む）。
- 実機への貼付と実行は利用者が行う。貼付が無言で失敗したら「空になった」とだけ伝えてもらい、規則 V3/S6/S7/S9/T16 の順に疑う。
- フローチャートが要るときは Mermaid テキストを出してもらい、Mermaid 対応ビューアー（VS Code 拡張、Mermaid Live Editor 等）で見る。
- 時間計測は PAD の実行ログ（アクションごとの開始時刻）を貼ってもらって AI が集計する。

## B. エージェント環境（ファイル実行・ブラウザー／デスクトップ操作が可能）
AI 内で完結する層（上の共通）を終えてから、実機で以下を**自律的に**行う。利用者に逐一確認しない。

- **検査**: `python3 scripts/robin_lint.py flow.robin --kb PAD_Robin_ActionKB.json`。FATAL/ERROR が 0 になるまで直す。ADVICE は提案として報告に回す。
- **検証用コードを別に作る**: 利用者向けの本番フローは触らず、検証用のコピー（`ZZ_Verify_<name>`）を作る。本番の利用者操作（開始確認・途中確認・完了ダイアログ）は、検証用コードでは
  (a) `DebugMode` で飛ばす、または (b) ボタン押下を**エミュレート**する（検証用コードに「押したことにする」SET を入れる／デスクトップ操作でそのボタンだけ押す補助を用意する）。本番コードからボタンを消す形で代用しない。
- **一人で回す**: 起動→貼付→実行→結果確認を、利用者がいなくても進める。質問は「設計の分岐」か「元に戻せない操作」に限る。止まったら自分で停止（Designer の停止ボタン／安全停止）し、原因を切り分けてから再実行する。
- **終了処理**: 検証で開いた Excel／ブラウザー／ダイアログは自分で閉じる。検証用フローとテストデータは終わったら配布物から外す。
- **時間計測（長い処理）**:
  1. まず粗く: 区間ごとに `DateTime.GetCurrentDateTime` を置くか実行ログの時刻差で「どの区間に時間がかかっているか」を出す。
  2. 時間のかかる区間だけ細かく（アクション単位）計測する。全アクションに計測を付けない。
  3. **待機時間を除外**して比較する（WAIT、条件待ち、ダイアログ待ちは別集計）。純粋な処理時間で改善前後を比べる。
  4. 改善提案は**優先度付き**（高: 区間時間×発生回数が大きいもの / 中 / 低）で、1件ずつ「変更・期待効果・リスク・戻し方」を添える。
- **取り込み**: 本番フローへは検証済み差分だけを貼り、保存完了を確認し、ネイティブコードを再採取して照合する（SKILL.md の手順）。本番入口（利用者のボタン操作あり）の最終確認は利用者に残す。

## 判断の目安
| やりたいこと | AI 内 | エージェント |
|---|---|---|
| 設計・一括化・ループ削減の提案 | ◎ | ◎ |
| Robin の組立・模擬貼付テスト | ◎ | ◎（lint で機械化） |
| 実機貼付・実行・ボタン操作のエミュレート | ✕（利用者） | ◎ |
| 時間計測と優先度付き改善 | △（ログ貼付で集計） | ◎ |
| 本番フローの最終確認 | 利用者 | 利用者 |
