# 00 モード（対話か自走か、どこまでやらせるか）

最近のコーディング支援ツールは「Ask／Plan／Agent／Auto」のようなモードと、モード間を渡す **仕様の成果物**
（要件→設計→タスク）で、対話と自走を使い分けている。このスキルも同じ形にする。
モードは**最初に1回だけ**決め、変えるときは利用者が一言（「自走で」「ここからは対話で」）言えばよい。

## 3つのモード

| モード | 想定環境 | 利用者の関与 | このスキルがやること |
|---|---|---|---|
| **Chat**（プロンプトだけ） | Microsoft 365 Copilot、Web チャット、ツール無し | 貼付・実行・結果報告はすべて利用者 | 01 計画 → 02 設計 → Robin 組立 → AI 内の模擬貼付テスト（判定表）→ 貼り方の説明。`scripts/make_prompt_pack.py` の出力を会話の先頭に貼って使う |
| **Interactive**（対話エージェント） | Claude（ファイル・実行・画面操作あり） | GO、設計確認、取り込み前の3点で承認。元に戻せない操作は都度承認 | 上に加えて lint、検証用フローでの実機確認、時間計測、優先度つき提案。1周ごとに結果を見せて次へ |
| **Autonomous**（自走） | 同上、無人 | 開始時に範囲・上限・禁止を承認。以後は聞かない | 06-autonomous-loop に従い、設計→組立→検査→検証→計測→改善を上限まで回し、朝の報告を出す |

## モードの決め方
- ツールが無い → Chat。ツールがあり利用者が居る → Interactive（既定）。「夜回して」「自走で」「GO したら朝まで」→ Autonomous。
- 不明なら Interactive で始め、計画カードの「検証方法」欄で確認する。

## モードをまたぐ成果物（spec）
どのモードでも同じ3つを作り、ファイルかメッセージとして残す。これが引き継ぎ資料であり、モードを変えても続きから進められる。
1. `plan.md` — 01-plan の計画カード（要件・方針・見積もり・リスク・検証方法・禁止）。GO の対象。
2. `design.md` — 02-design の処理順と「一括／ループ／再試行／チェックポイント」の指定。必要なら Mermaid。
3. `tasks.md` — 作業の箇条書き（組立する部品、確認が要る UI 要素、検証ケース、取り込み手順）。進捗はここに ✓ を付ける。
Chat モードではメッセージ内の見出しで代用し、エージェント環境では `work/` 配下のファイルにする。

## 承認ゲート（どのモードでも同じ3つ。Autonomous は1に集約）
1. **GO**（計画カードに同意）
2. **設計確認**（処理順と一括化・ループの扱い）
3. **本番取り込み**（検証済み差分を本番フローへ貼る前）
元に戻せない操作（削除・送信・本番上書き）はモードに関係なく承認か、検証用コードでの無効化が必要。

## 自律度の目安（利用者が言葉で指定できる）
- 「聞きながら」= Interactive で1周ごとに確認。
- 「任せる」= Interactive だがゲート3つ以外は聞かない。
- 「自走」= Autonomous。上限（時間・回数）と禁止事項を先に言ってもらう。言われなければ既定: 3時間・10周・送信系無効。
